## LOG\_LEVEL

Sets the level of logs to be displayed. The actual **options** parameter corresponding to this parameter is `log`.

**Parameter values:**

- **debug**: Outputs debug/info/warning/error level debug log information.
- **info**: Outputs info/warning/error level debug log information.
- **warning**: Outputs warning/error level debug log information.
- **error**: Outputs error level debug log information.
- **null**: (default value) Does not output debug logs.

**Configuration example:**

```c++
{ge::ir_option::LOG_LEVEL, "debug"}
```

**Applicable products:**

Supported on all chips.

## DEBUG\_DIR

Configures the path for saving debug-related intermediate files generated by operator compilation. Intermediate files include but are not limited to operator .o (operator binary file), .json (operator description file), and .cce files. By default, they are generated in the current path. The **options** parameter actually corresponding to this parameter is `ge.debugDir`.

**Constraints:**

- To specify the storage path of intermediate files generated by operator compilation, the **DEBUG\_DIR** parameter must be used together with the **OP\_DEBUG\_LEVEL** parameter. When **OP\_DEBUG\_LEVEL** is set to **0**, the **DEBUG\_DIR** parameter cannot be used.
- In addition to the **DEBUG\_DIR** parameter, the storage path of debug files generated by operator compilation can also be configured through the environment variable **ASCEND\_WORK\_PATH**. The priority of these methods is: configuration parameter "DEBUG\_DIR" \> environment variable ASCEND\_WORK\_PATH \> default storage path. For details about the environment variable **ASCEND\_WORK\_PATH**, see *[Environment Variable Reference](https://gitcode.com/cann/docs/blob/9.2.0/docs/en/env-vars/README.md)*.

**Configuration example:**

```c++
{ge::ir_option::OP_DEBUG_LEVEL, "1"},
{ge::ir_option::DEBUG_DIR, "/home/test/module/out_debug_info"}
```

**Applicable products:**

Supported on all chips.

## OP\_DEBUG\_LEVEL

Feature switch for operator compilation debugging. The actual **options** parameter corresponding to this parameter is `ge.opDebugLevel`.

To specify the path for storing intermediate files of operator compilation, use the **DEBUG\_DIR** parameter. When **OP\_DEBUG\_LEVEL** is set to **0**, the **DEBUG\_DIR** parameter does not take effect.

**Parameter values:**

- **0**: (Default value) Disables operator debugging. The operator compilation directory **kernel\_meta** is **not generated** in the current execution path.
- **1**: Enables operator debugging. Generates the **kernel\_meta** folder in the current execution path, and generates the \*.o file (operator binary file), the \*.json file (operator description file), and the TBE instruction mapping file (operator cce file \*.cce and python-cce mapping file \*\_loc.json) in the folder for subsequent analysis of AICore Error issues.

    <!-- npu="950" id1 -->
    Ascend 950PR&950DT products do not generate the TBE instruction mapping file.
    <!-- end id1 -->

- **2**: Enables operator debugging. Generates the **kernel\_meta** folder in the current execution path, and generates the \*.o file (operator binary file), the \*.json file (operator description file), and the TBE instruction mapping file (operator cce file \*.cce and python-cce mapping file \*\_loc.json) in the folder, for subsequent analysis of AICore Error issues. Setting the value to 2 also disables the compiler optimization switch and enables the ccec debugging feature (the CCE compiler option is set to -O0-g).

    <!-- npu="950" id2 -->
    Ascend 950PR&950DT products do not generate the TBE instruction mapping file.
    <!-- end id2 -->

- **3**: Disables operator debugging. Generates the **kernel\_meta** folder in the current execution path, and generates the *.o (operator binary) files and*.json (operator description) files in the folder, for reference when analyzing operator issues.
- **4**: Disables the operator debug feature, generates the **kernel\_meta** folder in the current execution path, and in that folder generates \*.o (operator binary file), \*.json file (operator description file), TBE instruction mapping file (operator cce file \*.cce), and UB fusion computation description file (\{**$kernel\_name\}\_compute.json**), which can be used for problem reproduction and precision comparison when analyzing operator issues.

    <!-- npu="950" id3 -->
    Ascend 950PR&950DT products do not generate the TBE instruction mapping file or the UB fusion computation description file.
    <!-- end id3 -->

> [!NOTE]
>
>- If **OP\_DEBUG\_LEVEL** is set to **0** and the **OP\_DEBUG\_CONFIG** parameter is also configured, the operator compilation directory **kernel\_meta** is retained in the current execution path in this scenario.
>- If **OP\_DEBUG\_LEVEL** is set to **0** and the **NPU\_COLLECT\_PATH** environment variable is also set, the compilation directory **kernel\_meta** is always retained; if the **ASCEND\_WORK\_PATH** environment variable is set, it is retained in the path specified by that environment variable; if the **ASCEND\_WORK\_PATH** environment variable is not set, it is retained in the current execution path.
>- During training execution, it is recommended to set the value to **0** or **3**. If problem locating is required, select debug switch options 1 and 2, because enabling the debug feature degrades network performance.
>- When set to **2** (that is, enabling the CCE compiler option), the operator Kernel (\*.o file) size increases. In dynamic shape scenarios, because the operator compilation traverses possible shape scenarios, the operator Kernel file may become too large to compile. In this case, it is recommended not to configure the CCE compiler option. An example of the error log caused by the operator Kernel file being too large to compile is as follows:
>
>   ```text
>   message:link error ld.lld: error: InputSection too large for range extension thunk ./kernel_meta_xxxxx.o
>    ```
>
>- When the debug feature switch is enabled, if the model contains the following general fusion operators, the \*.o, \*.json, and \*.cce files of these operators are not generated in the operator compilation directory **kernel\_meta**.
>
>   MatMulAllReduce
>
>   MatMulAllReduceAddRmsNorm
>
>   AllGatherMatMul
>
>   MatMulReduceScatter
>
>   AlltoAllAllGatherBatchMatMul
>
>   BatchMatMulReduceScatterAlltoAll

**Configuration example:**

```c++
{ge::ir_option::OP_DEBUG_LEVEL, "1"}
```

**Applicable products:**

Supported on all chips.

## OP\_DEBUG\_CONFIG

Feature switch for Global Memory detection. The actual **options** parameter corresponding to this parameter is `op_debug_config`.

**Parameter values:**

The value is the path to a .cfg configuration file. Multiple options in the configuration file are separated by commas:

- **oom**: During operator **execution**, detects whether Global Memory is accessed out of bounds.
  - When this option is configured, during operator compilation, the .o (operator binary) and .json (operator description) files are retained in the **kernel\_meta** folder generated by operator compilation in the current execution path.
  - After this option is used, the following detection logic is added during operator compilation. You can use the **dump\_cce** parameter to view the following code in the generated .cce file.

    ```cce
    inline __aicore__ void  CheckInvalidAccessOfDDR(xxx) {
        if (access_offset < 0 || access_offset + access_extent > ddr_size) {
            if (read_or_write == 1) {
                trap(0X5A5A0001);
            } else {
                trap(0X5A5A0002);
            }
        }
    }
    ```

- **dump\_cce**: During operator compilation, the operator cce file \*.cce, as well as the .o (operator binary) and .json (operator description) files, are retained in the **kernel\_meta** folder generated by operator compilation in the current execution path.
- **dump\_loc**: During operator compilation, the python-cce mapping file \*\_loc.json, as well as the .o (operator binary) and .json (operator description) files, are retained in the **kernel\_meta** folder generated by operator compilation in the current execution path.
- **ccec\_O0**: During operator compilation, enables the CCE compiler option -O0. Configuring this option does **not** optimize the debug information, and is used for subsequent analysis of AI Core Error issues.
- **ccec\_g**: During operator compilation, enables the CCE compiler option -g. Configuring this option **does** perform optimization on debug information, for subsequent analysis of AI Core Error issues.
- **check\_flag**: During operator **execution**, detects whether the internal pipeline synchronization signals of the operator match.
  - When this option is configured, during operator compilation, the .o (operator binary) and .json (operator description) files are retained in the **kernel\_meta** folder generated by operator compilation in the current execution path.
  - After this option is used, the following detection logic is added during operator compilation. Users can then use the **dump\_cce** parameter to view the following code in the generated .cce file.

    ```cce
        set_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID0);
        set_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID1);
        set_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID2);
        set_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID3);
        ....
        pipe_barrier(PIPE_MTE3);
        pipe_barrier(PIPE_MTE2);
        pipe_barrier(PIPE_M);
        pipe_barrier(PIPE_V);
        pipe_barrier(PIPE_MTE1);
        pipe_barrier(PIPE_ALL);
        wait_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID0);
        wait_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID1);
        wait_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID2);
        wait_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID3);
        ...
    ```

    During actual inference execution, if the internal pipeline synchronization signals of the operator do not match, a timeout error is ultimately reported **at the problematic operator, and the program is terminated**. An example of the error message is:

    ```text
    Aicore kernel execute failed, ..., fault kernel_name=operator name,...
    rtStreamSynchronizeWithTimeout execute failed....
    ```

**Configuration example:**

```c++
{ge::ir_option::OP_DEBUG_CONFIG, "/root/test0.cfg"}
```

The information in the **test0.cfg** file is as follows:

```text
op_debug_config=ccec_g,oom
```

**Constraints:**

During operator compilation, if users do not want to build all AI Core operators but instead specify certain AI Core operators to build, they need to add the **OP\_DEBUG\_LIST** field to the **test0.cfg** configuration file above. During operator compilation, only the operators specified in this list are built, and they are built according to the options configured by **OP\_DEBUG\_CONFIG**. The requirements for the **OP\_DEBUG\_LIST** field are as follows:

- Supports specifying operator names or operator types.
- Operators are separated by English commas. If an operator type is specified, configure it in the **OpType::TypeName** format. Mixed configuration of operator types and operator names is supported.
- The operators to be built must be placed in the configuration file specified by the **OP\_DEBUG\_CONFIG** parameter.

The configuration example is as follows. Add the following information to the **test0.cfg** file:

```c++
op_debug_config=ccec_g,oom
op_debug_list=GatherV2,opType::ReduceSum
```

During model compilation, the ***GatherV2,ReduceSum*** operators are built according to the **ccec\_g** and **oom** options.

> [!NOTE]
>
>- When the CCE compiler option is enabled (that is, the **ccec\_O0** or **ccec\_g** option), the size of the operator Kernel (the \*.o file) increases. In dynamic shape scenarios, because all possible scenarios are traversed during operator compilation, the operator Kernel file may eventually become too large to compile. In this case, it is recommended not to enable the CCE compiler option. The log displayed when the operator Kernel file is too large to compile is as follows:
>
>   ```text
>   message:link error ld.lld: error: InputSection too large for range extension thunk ./kernel_meta_xxxxx.o
>    ```
>
>- The CCE compiler options **ccec\_O0** and **oom** cannot be enabled at the same time, which may cause an AICore Error. An example of the error message is as follows:
>
>   ```text
>   ...there is an aivec error exception, core id is 49, error code = 0x4 ...
>   ```
>
>- If the **NPU\_COLLECT\_PATH** environment variable is configured, enabling the switch for detecting whether Global Memory is out of bounds (configure **oom** in the configuration file specified by **OP\_DEBUG\_CONFIG**) is not supported. Otherwise, the compiled model file or operator Kernel package will report an error when used.
>- When the compiler options **oom**, **dump\_cce**, and **dump\_loc** are configured, if the model contains the following general fusion operators, the \*.o, \*.json, and \*.cce files of these operators will not be generated in the operator compilation directory **kernel\_meta**.
>
>   MatMulAllReduce
>
>   MatMulAllReduceAddRmsNorm
>
>   AllGatherMatMul
>
>   MatMulReduceScatter
>
>   AlltoAllAllGatherBatchMatMul
>
>   BatchMatMulReduceScatterAlltoAll

**Applicable products:**

Supported on all chips.

## OPTION\_EXPORT\_COMPILE\_STAT

Configures whether to generate a result file **fusion\_result.json** of operator fusion information (including graph fusion and UB fusion) during graph compilation. The actual **options** parameter corresponding to this parameter is `ge.exportCompileStat`.

This file records the fusion patterns used during graph compilation. In the file:

- **session\_and\_graph\_id\_*xx\_xx***: Indicates the thread and graph number to which the fusion result belongs.
- **graph\_fusion**: Indicates graph fusion.
- **ub\_fusion**: Indicates UB fusion.

    <!-- npu="950" id4 -->
    **Ascend 950PR&950DT series products do not support UB fusion, so this information is not generated**.
    <!-- end id4 -->

- **match\_times**: Indicates the number of times the fusion patterns are matched during graph compilation.
- **effect\_times**: Indicates the number of times it actually takes effect.
- **repository\_hit\_times**: Indicates the number of hits in the optimized UB fusion repository.

    <!-- npu="950" id5 -->
    **Ascend 950PR&950DT products do not support UB fusion and do not generate this information**.
    <!-- end id5 -->

**Parameter values:**

- **0**: Does not generate the operator fusion information result file.
- **1**: (Default value) Generates the operator fusion information result file when the program exits normally.
- **2**: Generates the operator fusion information result file when graph compilation is complete. That is, if graph compilation is complete, the operator fusion information result file is still generated even if the program is interrupted early.

> [!NOTE]
>
>- If the **ASCEND\_WORK\_PATH** environment variable is not set, the result file is generated in the current path of the execution script by default. If the **ASCEND\_WORK\_PATH** environment variable is set, the save path is: **$ASCEND\_WORK\_PATH/FE/$\{ process ID \}/fusion\_result.json**. For details about the environment variable, see [*Environment Variable Reference*](https://gitcode.com/cann/docs/blob/9.2.0/docs/en/env-vars/README.md).
>- Fusion patterns disabled through the **FUSION\_SWITCH\_FILE** parameter do not appear in the **fusion\_result.json** file.

**Configuration example:**

```c++
{ge::ir_option::OPTION_EXPORT_COMPILE_STAT, "1"}
```

**Applicable products:**

Supported on all chips.
