# Graph Build Cache

<!-- md-trans-meta sourceCommit=24fb17e3715fbd5097e72e1018d9d79c241fb875 translatedAt=2026-10-21T09:59:06.440Z pushedAt=2026-10-28T08:37:50.230Z nl=2 -->

The graph compilation cache feature supports persisting graph compilation results to disk, so that when the application runs again, the cached compilation results on the disk can be loaded directly. During the process of **building and running the graph**, you can enable the graph compilation cache feature to reduce the graph compilation time.

<!-- npu="310b" id1 -->
Atlas 200I/500 A2 inference products do not support this feature.
<!-- end id1 -->

## Constraints

- The cache file is determined by ge.graph\_compiler\_cache\_dir and ge.graph\_key in the options parameter. If the cache file does not exist, the cache is saved; if it exists, the cache is loaded directly. The feature takes effect only when both ge.graph\_compiler\_cache\_dir and ge.graph\_key are configured as non-empty.
- The cache directory specified by ge.graph\_compiler\_cache\_dir must exist; otherwise, compilation fails.
- The uniqueness of ge.graph\_key must be ensured by the user; otherwise, if a cache with the same ge.graph\_key already exists, the corresponding cache is loaded directly.
- In a multi-process scenario, if different graphs use the same graph key and cache dir, the graph that triggers caching later will not be actually compiled; instead, it loads the graph cached earlier.
- After the graph changes, the original cache file becomes unavailable. The user needs to manually delete the cache files in the cache directory or modify ge.graph\_key, and then recompile to generate the cache file.
- Compatibility of caches across versions cannot be guaranteed. If the version is upgraded, the cache directory must be cleared and the cache regenerated by recompilation.

## Usage

```c++
std::map<ge::AscendString, ge::AscendString> session_options = {{"ge.graph_compiler_cache_dir", "./build_cache_dir"}};
std::shared_ptr<ge::GeSession> session = std::make_shared<ge::GeSession>(session_options);
const auto graph = CreateGraph();
std::map<ge::AscendString, ge::AscendString> graph_options = {{"ge.graph_key", "test_graph_001"}};
ge::Status ret = session->AddGraph(0, graph, graph_options);
...
```

## Cache File Generation Rules

The generated files include:

- Model cache file
- Index file, which helps you quickly locate the corresponding cache file through graph\_key. The following is an example of the index file content:

    ```json
    {
        "cache_file_list":[
            {
                "cache_file_name":"./cache_dir/graph_$key1_20230117202307.om",
                "graph_key":"graph_$key1",
                "var_desc_file_name":"./cache_dir/graph_$key1_20230117202307.rdcpkt"
            },
            {
                "cache_file_name":"./cache_dir/graph_$key1_20230117203007.om",
                "graph_key":"graph_$key1",
                "var_desc_file_name":"./cache_dir/graph_$key1_20230117203007.rdcpkt"
            }
        ]
    }
    ```

- Variable format file, which is generated only when variables exist in the graph. It is used by the framework to match the model cache file. If the variable format in the graph corresponding to graph\_key changes, the previously cached cache files cannot be directly restored and used. In this case, the compilation process is triggered again to regenerate the cache files.
- If the external weight feature is enabled, that is, the ge.externalWeight parameter is configured in the options and set to 1, a weight directory is also generated in the path specified by **ge.graph\_compiler\_cache\_dir** to store the weight information of the Const/Constant nodes in the original network.

File naming rules:

- The index file is named ge.graph\_key + ".idx".
- The model cache file is named ge.graph\_key + timestamp + ".om".
- The variable format file is named ge.graph\_key + timestamp + ".rdcpkt".
