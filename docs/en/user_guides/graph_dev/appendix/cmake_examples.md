- Basic usage

    ```cmake
    # 1. Define the prototype dynamic library (prerequisite).
    add_library(opgraph_math SHARED
    )
    # 2. Generate the ES API package (library + wheel package).
    add_es_library_and_whl(
        ES_LINKABLE_AND_ALL_TARGET es_math
        OPP_PROTO_TARGET  opgraph_math
        OUTPUT_PATH       ${CMAKE_BINARY_DIR}/output
    )

    # 3. Use it in the app.
    add_executable(my_app main.cpp)
    target_link_libraries(my_app PRIVATE es_math)
    ```

    If the project also contains intermediate OBJECT/STATIC targets that require ES header files at the compilation stage, you can additionally add add\_dependencies\(\<intermediate target\> build\_es\_math\)(the build\_es\_\*\*\* name varies with the package name) to ensure that code generation is completed before the target is compiled. The final executable or shared library only requires target\_link\_libraries\(... es\_math\) to automatically trigger the related dependencies, as shown in the following example:

    ```cmake
    add_library(my_obj OBJECT foo.cc bar.cc)
    # Ensure that the build_es_math target is executed before compiling my_obj. This is usually used for prerequisite operations such as generating dependent header files.
    # For example, the es_math header file is generated by build_es_math.
    add_dependencies(my_obj build_es_math)
    # Pass the header file search path of es_math to my_obj.
    target_link_libraries(my_obj PRIVATE es_math)

    # Create the executable my_app, using the object files generated in my_obj ($<TARGET_OBJECTS:my_obj>).
    add_executable(my_app $<TARGET_OBJECTS:my_obj>)
    # Link the es_math dependency to my_app (optional).
    target_link_libraries(my_app PRIVATE
            es_math
    )
    ```

- Generate only the C/C++ library

    ```cmake
    # Generate only the C/C++ library (skip the Python wheel package).
    add_es_library(
        ES_LINKABLE_AND_ALL_TARGET es_math
        OPP_PROTO_TARGET  opgraph_math
        OUTPUT_PATH       ${CMAKE_BINARY_DIR}/output
    )
    ```

- Do not generate some operators.

    ```cmake
    # Generate the math target.
    # The generated products will not include es_Add_c.h; es_Add.h, es_Add.cpp, and es_Add.py.
    add_es_library(
        ES_LINKABLE_AND_ALL_TARGET es_math
        OPP_PROTO_TARGET  opgraph_math
        OUTPUT_PATH       ${CMAKE_BINARY_DIR}/output
        EXCLUDE_OPS       Add
    )
    ```

- Multiple targets.

    ```cmake
    # Generate the math target.
    add_es_library_and_whl(
        ES_LINKABLE_AND_ALL_TARGET es_math
        OPP_PROTO_TARGET  opgraph_math
        OUTPUT_PATH       ${CMAKE_BINARY_DIR}/output
    )

    # Generate the nn target.
    add_es_library_and_whl(
        ES_LINKABLE_AND_ALL_TARGET es_nn
        OPP_PROTO_TARGET  opgraph_nn
        OUTPUT_PATH       ${CMAKE_BINARY_DIR}/output
    )

    # Use multiple targets.
    add_executable(my_inference_app main.cpp)
    target_link_libraries(my_inference_app PRIVATE
        es_math
        es_nn
    )
    ```

- Multiple targets share the output directory. All targets can use the same **OUTPUT\_PATH**, and header files are organized in subdirectories by package name, as shown in the following example:

    ```cmake
    add_es_library_and_whl(
        ES_LINKABLE_AND_ALL_TARGET es_math
        OPP_PROTO_TARGET  opgraph_math
        OUTPUT_PATH       ${CMAKE_BINARY_DIR}/output  # Shared path
    )

    add_es_library_and_whl(
        ES_LINKABLE_AND_ALL_TARGET es_nn
        OPP_PROTO_TARGET  opgraph_nn
        OUTPUT_PATH       ${CMAKE_BINARY_DIR}/output  # Shared path
    )

    # Output structure:
    # output/
    # ├── include/
    # │   ├── es_math/
    # │   └── es_nn/
    # ├── lib64/
    # │   ├── libes_math.so
    # │   └── libes_nn.so
    # └── whl/
    #     ├── es_math-1.0.0-py3-none-any.whl
    #     └── es_nn-1.0.0-py3-none-any.whl
    ```
