# Codegen

The function of Codegen is to parse the ImplGraph generated by Schedule and generate actually executable code, including code that runs on the host side (Host Code) and the device side (Kernel Code), where:

- Host Code: code executed on the host side, including the following:
  - tiling\_func: responsible for dividing the computation task into smaller blocks (tiling) for efficient execution on the device.
  - infer\_shape: infers the shape of each tensor to ensure the correctness of subsequent computation.
  - get\_kernel: obtains and generates the kernel code on the device side.

- Kernel Code: kernel code executed on the device side, including the following:
  - kernel: the specific computation logic.
  - tiling\_data: a structure used to describe how data is divided and processed.

The input of Codegen is the ImplGraph generated by Schedule. This graph contains basic elements for code generation, such as shape information, node information, and axis information. An example of ImplGraph is as follows:

Based on the ImplGraph parsing, the following example code shows the process by which Codegen generates the DataCopy API. It can be seen that the core process includes parsing the splitting strategy on the graph, assembling the input parameters of the API, and generating the code to be executed on the Device side.

```c++
ss << "DataCopyPadExtend(" << ub << ", " << gm << "[" << gm_offset << " + " << tpipe.tiler.Size(api_attr.offset)
   << "], " << dma_param.block_count << ", " << dma_param.block_len << ", " << dma_param.src_stride << ", "
   << dma_param.dst_stride << ");" << std::endl;
```

Similar to traditional operator code, for different tiling strategies, Schedule generates multiple templates corresponding to different ImplGraphs. Codegen needs to parse these templates in sequence, generate template functions, and call different template functions at the kernel function entry based on tiling\_key. Example:

```c++
extern "C" __global__ __aicore__ void abs_test(GM_ADDR abs_test_Data_0, GM_ADDR abs_test_Output_0, GM_ADDR workspace, AutofuseTilingData param) {
  const AutofuseTilingData t;
    if (t.tiling_key == 0) {
      abs_test_0_general_0_nil_2_nil(abs_test_Data_0, abs_test_Output_0, workspace, t);
    } else if (t.tiling_key == 1) {
      abs_test_0_general_0_nil_2_nil_unaligned(abs_test_Data_0, abs_test_Output_0, workspace, t);
    }
}
```

The preceding AutofuseTilingData structure is shown as follows. The specific values of its member variables, including tiling\_key, are calculated by ATT:

```c++

```

Different template functions generate different for loops and process different amounts of data each time. Example:

- tiling\_key=0

    The z1 axis is tiled, and the vectorization axis for which computation is completed in the UB each time is z1t.

    ```c++
    for (int z0z1Tb = 0; z0z1Tb < z0z1Tb_loop_size; z0z1Tb++) {
        Abs(y_local[0], xlocal[0], z1t_actual_size);
    }
    ```

- tiling\_key=1

    The z0 axis is tiled, and the vectorization axes for which computation is completed in the UB each time are z0t and z1.

    ```c++
    for (int z0Tb = 0; z0Tb < z0Tb_loop_size; z0Tb++) {
        Abs(y_local[0], xlocal[0], z0t_actual_size * z1_axis_size);
    }
    ```

Overall, Codegen generates kernel code based on the ImplGraph. However, to continuously improve the performance of kernel code, it is still necessary to keep exploring both Codegen framework optimization and API internal optimization.
