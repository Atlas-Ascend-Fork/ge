# ES Overview

This section introduces a minimalist approach to graph construction, aiming to improve the ease of graph construction.

ES (Eager Style) is a set of **function-style graph construction APIs**. Its syntax is similar to that of Torch Eager mode scripts, hence the name Eager Style. It expresses edge connections and passes IR (Intermediate Representation) information through functions. Compared with the approach of [Graph Construction from Operator Prototypes](../construct_graph/construct_graph_using_op_proto.md), ES graph construction requires less code, improving the ease of graph construction while providing a certain degree of error prevention. The overall logical view is as follows:

![](../figures/cann_architecture_5.png)

ES consists of three key components:

- **ES basic data structures**: Provide basic data structure APIs for ES graph construction, such as [EsGraphBuilder](../../../api/graph_engine_api/cpp/ge/es/EsGraphBuilder/overview.md) and [EsTensorHolder](../../../api/graph_engine_api/cpp/ge/es/EsTensorHolder/overview.md). For details, see [ES Interface](../../../api/graph_engine_api/cpp/ge/es/es_interface.md).
- **ES Code Generator**: Reads operator prototypes and generates an executable program for the graph construction API of each operator.
- **Generated** **ES graph construction APIs**: Graph construction APIs that are generated by the ES Code Generator at build time or already included in the CANN software package and can be directly used by users.

The ES graph construction APIs have the following features:

- Automatically generated through CodeGen based on operator prototypes.
- Supports multiple languages: C, C++, and Python.
- Supports forward and backward compatibility from three dimensions: API, ABI, and IR semantics.

## Mapping Between ES Graph Construction APIs and IR

In all three languages, the mapping logic between ES graph construction APIs and IR is the same: each IR is mapped to a function, whose name is derived from the IR type (with an `Es` prefix in the C interface). The function parameters correspond to the operator inputs and attributes in sequence, and the return value corresponds to the output.

For example, the IR prototype definition of operator Foo is as follows:

```c++
REG_OP(Foo)
    .INPUT(x1)
    .INPUT(x2)
    .OUTPUT(y1)
    .ATTR(a1, Int, 10)
    .ATTR(a2, Int, 20)
    .OP_END_FACTORY_REG(Foo)
```

In the preceding IR prototype definition, the operator type is Foo, the operator inputs are x1 and x2, the output is y1, and the attributes are a1 and a2 (with default values 10 and 20, respectively). In the ES graph construction API, the corresponding function prototype is:

- Function name: Foo (C++/Python) or EsFoo (C).
- Parameters: 4 in total, namely x1, x2, a1, and a2 in sequence.
- Return value: output y1.

Based on the preceding principles, the generated ES graph construction API function prototype examples are as follows:

- C language

    ```c
    EsCTensorHolder* EsFoo(EsCTensorHolder* x1, EsCTensorHolder* x2, int64_t a1,  int64_t a2);
    ```

- C++ language

    ```c++
    namespace ge {
    namespace es {
    EsTensorHolder Foo(const EsTensorLike &x1, const EsTensorLike &x2, int64_t a1 = 10,  int64_t a2 = 20);
    }
    }
    ```

    In C++:

    1. Use the TensorLike type to express inputs, so that arguments can directly pass values, for example, Foo\(t0, float\(1.0\)\).
    2. To express that certain attributes in the IR prototype are optional, you can identify them by setting default parameters in the ES graph construction API function prototype.

- Python

    ```python
    def Foo(x1: Union[TensorHolder, TensorLike], x2: Union[TensorHolder, TensorLike], *, a1: int = 10, a2: int = 20) -> TensorHolder:
    ```

    In Python, positional parameters represent inputs, and keyword parameters represent attributes. This approach clearly distinguishes inputs from attributes and facilitates extension and compatibility.

## Header File/Module Splitting Strategy

Each IR prototype definition corresponds to an independent header file (for C and C++) and a corresponding Python module (.py file) in ES. For example, the ES header file generated for the preceding Foo IR prototype definition is:

- C language: es\_Foo\_c.h
- C++ language: es\_Foo.h
- Python language: es\_Foo.py

To improve the multi-language experience, ES also provides aggregate APIs. For the naming rules of individual header files and aggregate files, see [Product Description](generate_es_graph_api_optional.md#product-description).
