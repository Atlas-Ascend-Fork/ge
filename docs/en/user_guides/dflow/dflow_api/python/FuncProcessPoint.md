## Function

Constructor of FuncProcessPoint. It returns a FuncProcessPoint object.

## Prototype

```python
class FuncProcessPoint(compile_config_path: Optional[str] = None, name: Optional[str] = None,
py_func: Optional = None, workspace_dir: Optional = None)
```

## Parameters

| Parameter | Data Type | Value Description |
| --- | --- | --- |
| compile_config_path | str | Compilation configuration file of the UDF. It is mutually exclusive with py_func. After py_func is passed in, compile_config_path does not take effect. |
| name | str | Name of the processing point. The framework automatically ensures that the name is unique. If it is not set, names such as FuncProcessPoint, FuncProcessPoint_1, FuncProcessPoint_2, ... are automatically generated. |
| py_func | class | Custom Python UDF class developed by the user (proc_wrapper(func_list="ix:ox") must be used to register the input and output). It is mutually exclusive with compile_config_path. After py_func is passed in, compile_config_path does not take effect. |
| workspace_dir | str | Temporary workspace directory of the automatically generated Python UDF. It is used together with py_func. <br>If this field is empty, the name of py_func is concatenated with "_ws" and used. |

An example of the UDF compilation configuration file is as follows:

    ```
    {"func_list":[{"func_name":"Add", "inputs_index":[1,0], "outputs_index":[0]}],"input_num":2,"output_num":1,"target_bin":"libadd.so","workspace":"./","cmakelist_path":"CMakeLists.txt","compiler": "./cpu_compile.json","running_resources_info":[{"type":"cpu","num":2},{"type":"memory","num":100}],"heavy_load":false}
    ```

| func_list.inputs_index | Optional | The value is a list. The element is a number, indicating which inputs of FuncProcessPoint this function takes. | compiler | Optional | The value is a string, indicating the path configuration file of the cross-compilation tool for compiling source code in a heterogeneous environment. If it is not specified, the default compilation tool of the resource type is used.|
| running_resources_info | Optional | The value is a list, indicating the resource information required to run the current .so file. The element is the description of a single resource information item. |

buf\_cfg An example of the json configuration content and the explanation of each field are as follows.

    ```
    "buf_cfg":[{"total_size":2097152,"blk_size":256,"max_buf_size":8192,"page_type":"normal"},        // 1.total:2M  max:8K
               {"total_size":10485760,"blk_size":4096,"max_buf_size":8388608,"page_type":"normal"},   // 2.total:10M  max:8M
               {"total_size":2097152,"blk_size":256,"max_buf_size":8192,"page_type":"huge"},          // 3.total:2M  max:8K
               {"total_size":10485760,"blk_size":8192,"max_buf_size":8388608,"page_type":"huge"},     // 4.total:10M  max:8M
               {"total_size":69206016,"blk_size":8192,"max_buf_size":67108864,"page_type":"huge"}]    // 5.total:66M  max:64M
      ```

Note:
<br>- The sample above configures five memory gears in total. The first two are for normal memory, and the last three are for large page memory.
<br>- After the memory management module is initialized with this configuration, if the process applies for 8M large page memory, the driver generates and manages a 10M memory pool based on the fourth configuration item and applies for 8M memory from it.
<br>- If the process needs to apply for 1M large page memory again, because the third configuration item allows a maximum of only 8K per application, the request still falls into the memory pool corresponding to the fourth configuration item. In this case, only 8M of the previously applied 10M was used, and the remaining memory is still greater than 1M. Therefore, 1M memory is applied for from the previously generated 10M memory pool for this use.

<br>The default gears are as follows:

| ID | total_size | blk_size | max_buf_size | page_type |
| --- | --- | --- | --- | --- |
| 0 | 2M | 256B | 8K | normal |
| 1 | 32M | 8K | 8M | normal |
| 3 | 2M | 256B | 8K | huge |
| 4 | 66M | 8K | 64M | huge |

**Table 3**  buf\_cfg json configuration description

| Configuration Item | Optional/Mandatory | Description |
| --- | --- | --- |
| total_size | Required | Size of the memory pool at the current gear, in Byte<br>Constraint:<br>For normal memory, total_size is a multiple of 4K. For large page memory, total_size is a multiple of 2M. total_size is also a multiple of blk_size. |
| blk_size | Required | Minimum memory value that can be applied for at a time at the current gear, in Byte<br>Constraint:<br>The value must satisfy 2^n, be within (0,2M], and be less than max_buf_size. |
| max_buf_size | Required | Maximum memory value that can be applied for at a time at the current gear, in Byte<br>Constraint: less than total_size |
| page_type | Required | Memory type corresponding to the current gear.<br>Constraint:<br>Valid values are huge or normal, indicating large page memory and normal memory respectively. |

The CMakeLists file content is as follows:
<br>The DataFlow UDF compilation module parses the resource.json resource configuration and the cpu\_compiler configuration in the heterogeneous environment, and selects the cross-compilation tool specified in cpu\_compiler based on the resource type matched in resource.json. If the user does not specify the cpu\_compiler.json configuration file or cpu\_compiler.json does not configure the compilation tool for this type, the default compilation tool in the environment is used for compilation. The compilation tool names and paths for different resource types are as follows. $\{INSTALL\_DIR\} must be replaced with the file storage path after CANN software installation. If the Ascend-cann-toolkit package is installed, taking root installation as an example, the file storage path after installation is: /usr/local/Ascend/cann.

  - In X86 and Aarch scenarios: g++
  - In the Ascend scenario: $\{INSTALL\_DIR\}/toolkit/toolchain/hcc/bin/aarch64-target-linux-gnu-g++

    The user's source code project must comply with the following rules:

  - The source code project directory provided by the user must include all execution code and dependency library source code.
  - The user must configure the compilation script for the FuncProcessPoint execution code and dependent libraries.
  - The compilation script must use the RELEASE\_DIR variable as the final output directory. If there are dependent so files, the user must copy them to this path.
  - The compilation script must use the RESOURCE\_TYPE variable to determine the resource type. If the current UDF does not support a resource type, uncomment the corresponding comment.
  - A CMakeLists sample is as follows:

        ```
        cmake_minimum_required(VERSION 3.5)
        PROJECT(UDF)
        if ("x${RESOURCE_TYPE}" STREQUAL "xAscend")
          message(STATUS "ascend compiler enter")
          # if unsupported current resource type, please uncomment the next line.
          # message(FATAL_ERROR "Unsupported compile Ascend target!")
        elseif("x${RESOURCE_TYPE}" STREQUAL "xAarch")
          message(STATUS "aarch64 compiler enter")
          # if unsupported current resource type, please uncomment the next line.
          # message(FATAL_ERROR "Unsupported compile Aarch64 target!")
        else()
          message(STATUS "x86 compiler enter")
          # if unsupported current resource type, please uncomment the next line.
          # message(FATAL_ERROR "Unsupporte'd compile X86 target!")
        endif()

        if(DEFINED ENV{ASCEND_HOME_PATH})
          set(ASCEND_HOME_PATH $ENV{ASCEND_HOME_PATH})
          message(STATUS "Read ASCEND_HOME_PATH from ENV: ${ASCEND_HOME_PATH}")
        else()

          message(FATAL_ERROR "ASCEND_HOME_PATH is not set, please export ASCEND_HOME_PATH based on actual installation path.")
        endif()

        # set dynamic library output path
        set(CMAKE_LIBRARY_OUTPUT_DIRECTORY ${PROJECT_BINARY_DIR}/${RELEASE_DIR})
        # set static library output path
        set(CMAKE_ARCHIVE_OUTPUT_DIRECTORY ${PROJECT_BINARY_DIR}/${RELEASE_DIR})

        message(STATUS "CMAKE_LIBRARY_OUTPUT_DIRECTORY= ${CMAKE_LIBRARY_OUTPUT_DIRECTORY}")

        set(INC_DIR "${ASCEND_HOME_PATH}/include")flow_func")
        file(GLOB SRC_LIST "*.cpp")

        # Specify cross compiler
        add_definitions(-D_GLIBCXX_USE_CXX11_ABI=0)

        # set c++ compiler
        set(CMAKE_CXX_COMPILER ${TOOLCHAIN})

        # =========================UDF so compile============================
        # check if SRC_LIST exists
        if("x${SRC_LIST}" STREQUAL "x")
            message(UDF "=========no source file=============")
            add_custom_target(${UDF_TARGET_LIB}
                COMMAND echo "no source to make lib${UDF_TARGET_LIB}.so")
            return(0)
        endif()

        add_library(${UDF_TARGET_LIB} SHARED
          ${SRC_LIST}
        )

        target_include_directories(${UDF_TARGET_LIB} PRIVATE
          ${INC_DIR}
        )

        target_compile_options(${UDF_TARGET_LIB} PRIVATE
          -O2
          -std=c++11
          -ftrapv
          -fstack-protector-all
          -fPIC
        )

        if ("x${RESOURCE_TYPE}" STREQUAL "xAscend")
          target_link_libraries(${UDF_TARGET_LIB} PRIVATE
            -Wl,--whole-archive
            ${ASCEND_HOME_PATH}/devlib/device/libflow_func.so
            -Wl,--no-whole-archive
          )
          # if there are any dependent so, please release the following comments and copy dependent so to ${PROJECT_BINARY_DIR}/${RELEASE_DIR}
          # [[execute_process(
            COMMAND cp libdepend_xxx.so ${PROJECT_BINARY_DIR}/${RELEASE_DIR}
          )]]
        elseif("x${RESOURCE_TYPE}" STREQUAL "xAarch")
          target_link_libraries(${UDF_TARGET_LIB} PRIVATE
            -Wl,--whole-archive
           ${ASCEND_HOME_PATH}/devlib/linux/aarch64/libflow_func.so
            -Wl,--no-whole-archive
          )
          # if there are any dependent so, please release the following comments and copy dependent so to ${PROJECT_BINARY_DIR}/${RELEASE_DIR}
          # [[execute_process(
            COMMAND cp libdepend_xxx.so ${PROJECT_BINARY_DIR}/${RELEASE_DIR}
          )]]
        else()
          target_link_libraries(${UDF_TARGET_LIB} PRIVATE
            -Wl,--whole-archive
            ${ASCEND_HOME_PATH}/devlib/linux/x86_64/libflow_func.so
            -Wl,--no-whole-archive
          )
          # if there are any dependent so, please release the following comments and copy dependent so to ${PROJECT_BINARY_DIR}/${RELEASE_DIR}
          # [[execute_process(
             COMMAND cp libdepend_xxx.so ${PROJECT_BINARY_DIR}/${RELEASE_DIR}
          )]]
        endif()

        ```
