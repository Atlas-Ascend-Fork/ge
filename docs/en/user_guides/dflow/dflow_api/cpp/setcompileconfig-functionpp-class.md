## Function

Sets the name and path of the JSON configuration file of FunctionPp. This configuration file is used to map FunctionPp to a UDF.

Returns the configured FunctionPp.

## Prototype

```cpp
FunctionPp &SetCompileConfig(const char_t *json_file_path)
```

## Parameters

| Parameter | Input/Output | Description |
| --- | --- | --- |
| json_file_path | Input | Path and name of the JSON configuration file of FunctionPp.<br>The JSON configuration file of FunctionPp is used to describe and compile the UDF.<br>For the configuration file example and parameter description, see the following. |

The following is an example of the JSON configuration file of FunctionPp.

    ```
    {"func_list":[{"func_name":"Add", "inputs_index":[1,0], "outputs_index":[0]}],"input_num":2,"output_num":1,"target_bin":"libadd.so","workspace":"./","cmakelist_path":"CMakeLists.txt","compiler": "./cpu_compile.json","running_resources_info":[{"type":"cpu","num":2},{"type":"memory","num":100}],"heavy_load":false}
    ```

**Table 1** JSON configuration file of FunctionPp

| Configuration Item | Optional/Mandatory | Description |
| --- | --- | --- |
| workspace | Required | String value, indicating the workspace path of the UDF. |
| target_bin | Required | String value, indicating the name of the .so file generated by compiling the UDF project. To prevent illegal tampering, the string must be named in the format of lib***.so. Valid characters include uppercase and lowercase letters, digits, underscores (_), and hyphens (-). |
| input_num | Required | Numeric value, indicating the number of inputs of the UDF, that is, the number of inputs of FunctionPp. |
| output_num | Required | Numeric value, indicating the number of outputs of the UDF, that is, the number of outputs of FunctionPp. |
| func_list | Required | List value. Each element in the list describes a single function. Currently, only one function is supported. |
| func_list.func_name | Required | String value, indicating the function name, which must be consistent with the function name defined in the UDF. In the multi-function scenario, func_name must not be duplicated. |
| func_list.inputs_index | Optional | List value. Each element in the list is a number, indicating which inputs of FunctionPp are used by this function. This field is invalid in the single-function scenario. In the multi-function scenario, this field is mandatory, and the input indexes of multiple processing functions must not be shared or duplicated. |
| func_list.outputs_index | Optional | List value. Each element in the list is a number, indicating which outputs of FunctionPp correspond to this function. This field is invalid in the single-function scenario. In the multi-function scenario, the output indexes can be shared. |
| cmakelist_path | Optional | String value, indicating the path of the CMakeLists file for source code compilation relative to the workspace. If not specified, the default CMakeLists file under the workspace is used. |
| compiler | Optional | String value, indicating the path of the configuration file of the cross-compilation tool for compiling source code in a heterogeneous environment. If not specified, the default build tool of the resource type is used. |
| running_resources_info | Optional | List value, indicating the resource information required to run the current .so file. Each element in the list describes a single resource information item. |
| running_resources_info.type | Optional | Mandatory when running_resources_info is configured.<br>String value, indicating the type of resource information required to run the current .so file. The valid values are "cpu" and "memory". When the resource type is "memory", the unit is M. |
| running_resources_info.num | Optional | Mandatory when running_resources_info is configured.<br>Numeric value, indicating the quantity of resource information required to run the current .so file. |
| heavy_load | Optional | Indicates the computing power requirement of the node.<br><br>  - true: heavy load, indicating a high computing power requirement.<br>  - false: light load, indicating a low computing power requirement.<br><br>The default value is false.<br>When this parameter is set to "true", the deployment location of the UDF is affected. |
| buf_cfg | Optional | You can customize the memory pool levels. Custom levels can improve memory allocation efficiency and reduce memory fragmentation. If this parameter is not set, the default level configuration is used to initialize the memory module. This configuration supports a maximum of 64 levels. If more than 64 levels are configured, a compilation error is reported. |

The following is an example of the JSON configuration content of compiler and the description of each field.

    ```
    {"compiler":[{"resource_type":"X86","toolchain":"/usr/bin/g++"},{"resource_type":"Aarch","toolchain":"/usr/bin/g++"},{"resource_type":"Ascend","toolchain":"/usr/local/Ascend/hcc"}]}
    ```

**Table 2** JSON configuration description of compiler

| Configuration Item | Optional/Mandatory | Description |
| --- | --- | --- |
| compiler | Required | List value. Each element in the list describes the build tool of a single resource type. |
| compiler.resource_type | Required | String value, indicating the resource type supported by the device. |
| compiler.toolchain | Required | String value, indicating the path of the build tool corresponding to the resource type. |

The following is an example of the JSON configuration content of buf_cfg.

    ```
    "buf_cfg":[{"total_size":2097152,"blk_size":256,"max_buf_size":8192,"page_type":"normal"},        // 1.total:2M  max:8K
               {"total_size":10485760,"blk_size":4096,"max_buf_size":8388608,"page_type":"normal"},   // 2.total:10M  max:8M
               {"total_size":2097152,"blk_size":256,"max_buf_size":8192,"page_type":"huge"},          // 3.total:2M  max:8K
               {"total_size":10485760,"blk_size":8192,"max_buf_size":8388608,"page_type":"huge"},     // 4.total:10M  max:8M
               {"total_size":69206016,"blk_size":8192,"max_buf_size":67108864,"page_type":"huge"}]    // 5.total:66M  max:64M
    ```
<br>Note:
    <br>- In the preceding example, five memory levels are configured. The first two are for normal memory, and the last three are for large page memory.
    <br>- After the memory management module is initialized with this configuration, if the process requests 8 MB large page memory, the driver generates and manages a 10 MB memory pool based on the fourth configuration item, and allocates 8 MB memory from it.
    <br>- If the process needs to request 1 MB large page memory again, because a maximum of only 8 KB can be requested at a time according to the third configuration item, the request still falls into the memory pool corresponding to the fourth configuration item. In this case, only 8 MB of the 10 MB requested previously has been used, and the remaining memory is still greater than 1M. Therefore, 1 MBmemory is allocated from the previously generated 10 MB memory pool for this request.

<br>The default levels are as follows:

| ID | total_size | blk_size | max_buf_size | page_type |
| --- | --- | --- | --- | --- |
| 0 | 2M | 256B | 8K | normal |
| 1 | 32M | 8K | 8M | normal |
| 3 | 2M | 256B | 8K | huge |
| 4 | 66M | 8K | 64M | huge |

**Table 3** JSON configuration description of buf\_cfg

| Configuration Item | Optional/Required | Description |
| --- | --- | --- |
| total_size | Required | Size of the memory pool at the current level, in bytes.<br>Constraint: For normal memory, total_size must be a multiple of 4K. For large page memory, total_size must be a multiple of 2M. In addition, total_size must be a multiple of blk_size. |
| blk_size | Required | Minimum memory size that can be requested at a time at the current level, in bytes.<br>Constraint: blk_size must satisfy 2^n, fall within (0, 2M], and be smaller than max_buf_size. |
| max_buf_size | Required | Maximum memory size that can be requested at a time at the current level, in bytes.<br>Constraint: max_buf_size must be smaller than total_size, and max_buf_size must be strictly increasing within the same page_type. |
| page_type | Required | Memory type corresponding to the current level. The values are as follows.<br><br>  - huge: large page memory<br>  - normal: normal memory |

- CMakeLists file

    The DataFlow UDF compilation module parses the resource.json resource configuration and the cpu\_compiler configuration in the heterogeneous environment, and selects the cross-compilation build tool specified in cpu\_compiler based on the resource configuration type in resource.json. If the user does not specify the cpu\_compiler.json configuration file or cpu\_compiler.json does not configure a build tool of that type, the default build tool in the environment is used. The names and paths of the build tools for different resource types are as follows. Replace $\{INSTALL\_DIR\} with the file storage path after the CANN software is installed. If the Ascend-cann-toolkit package is installed, taking root installation as an example, the file storage path after installation is /usr/local/Ascend/cann.

  - In X86 and Aarch scenarios: g++
  - In Ascend scenarios: $\{INSTALL\_DIR\}/toolkit/toolchain/hcc/bin/aarch64-target-linux-gnu-g++

    The user's source code project must comply with the following rules:

  - The source code project directory provided by the user must include all execution code and dependency library source code.
  - The user must configure the build script for the FunctionPp execution code and dependency libraries.
  - The build script must use the RELEASE\_DIR variable as the final output directory. If there are dependent .so files, the user must copy them to this path.
  - The build script must use the RESOURCE\_TYPE variable to determine the resource type. If the current UDF does not support a resource type, uncomment the corresponding comment.
  - The following is a CMakeLists sample:

        ```
        cmake_minimum_required(VERSION 3.5)
        PROJECT(UDF)
        if ("x${RESOURCE_TYPE}" STREQUAL "xAscend")
          message(STATUS "ascend compiler enter")
          # if unsupported current resource type, please uncomment the next line.
          # message(FATAL_ERROR "Unsupported compile Ascend target!")
        elseif("x${RESOURCE_TYPE}" STREQUAL "xAarch")
          message(STATUS "aarch64 compiler enter")
          # if unsupported current resource type, please uncomment the next line.
          # message(FATAL_ERROR "Unsupported compile Aarch64 target!")
        else()
          message(STATUS "x86 compiler enter")
          # if unsupported current resource type, please uncomment the next line.
          # message(FATAL_ERROR "Unsupported compile X86 target!")
        endif()

        if(DEFINED ENV{ASCEND_HOME_PATH})
          set(ASCEND_HOME_PATH $ENV{ASCEND_HOME_PATH})
          message(STATUS "Read ASCEND_HOME_PATH from ENV: ${ASCEND_HOME_PATH}")
        else()

          message(FATAL_ERROR "ASCEND_HOME_PATH is not set, please export ASCEND_HOME_PATH based on actual installation path.")
        endif()

        # set dynamic library output path
        set(CMAKE_LIBRARY_OUTPUT_DIRECTORY ${PROJECT_BINARY_DIR}/${RELEASE_DIR})
        # set static library output path
        set(CMAKE_ARCHIVE_OUTPUT_DIRECTORY ${PROJECT_BINARY_DIR}/${RELEASE_DIR})

        message(STATUS "CMAKE_LIBRARY_OUTPUT_DIRECTORY= ${CMAKE_LIBRARY_OUTPUT_DIRECTORY}")

        set(INC_DIR "${ASCEND_HOME_PATH}/include/flow_func")
        file(GLOB SRC_LIST "*.cpp")

        # Specify cross compiler
        add_definitions(-D_GLIBCXX_USE_CXX11_ABI=0)

        # set c++ compiler
        set(CMAKE_CXX_COMPILER ${TOOLCHAIN})

        # =========================UDF so compile============================
        # check if SRC_LIST exists
        if("x${SRC_LIST}" STREQUAL "x")
            message(UDF "=========no source file=============")
            add_custom_target(${UDF_TARGET_LIB}
                COMMAND echo "no source to make lib${UDF_TARGET_LIB}.so")
            return(0)
        endif()

        add_library(${UDF_TARGET_LIB} SHARED
          ${SRC_LIST}
        )

        target_include_directories(${UDF_TARGET_LIB} PRIVATE
          ${INC_DIR}
        )

        target_compile_options(${UDF_TARGET_LIB} PRIVATE
          -O2
          -std=c++11
          -ftrapv
          -fstack-protector-all
          -fPIC
        )

        if ("x${RESOURCE_TYPE}" STREQUAL "xAscend")
          target_link_libraries(${UDF_TARGET_LIB} PRIVATE
            -Wl,--whole-archive
            ${ASCEND_HOME_PATH}/devlib/device/libflow_func.so
            -Wl,--no-whole-archive
          )
          # if there are any dependent so, please release the following comments and copy dependent so to ${PROJECT_BINARY_DIR}/${RELEASE_DIR}
          # [[execute_process(
            COMMAND libdepend_xxx.so ${PROJECT_BINARY_DIR}/${RELEASE_DIR}
          )]]
        elseif("x${RESOURCE_TYPE}" STREQUAL "xAarch")
          target_link_libraries(${UDF_TARGET_LIB} PRIVATE
            -Wl,--whole-archive
            ${ASCEND_HOME_PATH}/devlib/linux/aarch64/libflow_func.so
            -Wl,--no-whole-archive
          )
          # if there are any dependent so, please release the following comments and copy dependent so to ${PROJECT_BINARY_DIR}/${RELEASE_DIR}
          # [[execute_process(
            COMMAND cp libdepend_xxx.so ${PROJECT_BINARY_DIR}/${RELEASE_DIR}
          )]]
        else()
          target_link_libraries(${UDF_TARGET_LIB} PRIVATE
            -Wl,--whole-archive
            ${ASCEND_HOME_PATH}/devlib/linux/x86_64/libflow_func.so
            -Wl,--no-whole-archive
          )
          # if there are any dependent so, please release the following comments and copy dependent so to ${PROJECT_BINARY_DIR}/${RELEASE_DIR}
          # [[execute_process(
            COMMAND cp libdepend_xxx.so ${PROJECT_BINARY_DIR}/${RELEASE_DIR}
          )]]
        endif()

        ```
