# What Is a Single Operator Description File

<!-- md-trans-meta sourceCommit=6910bdd915e3528be24078d698c2568ed03b113b translatedAt=2026-10-27T14:36:39.780Z pushedAt=2026-10-28T10:39:42.310Z nl=2 -->

A single operator description file is a definition file for a single operator defined based on Ascend IR. It contains information such as the inputs, outputs, and attributes of the operator. After the file is converted into an offline model adapted to the AI processor, the function of the single operator can be verified.

A single operator description file is a JSON file composed of an OpDesc array. Its parameters and their descriptions are as follows:

**Table 1** OpDesc parameters<a id="table1"></a>

| Attribute Name | Type | Description | Required |
| --- | --- | --- | --- |
| compile_flag | INT32 | This parameter is deprecated and not recommended. It will be deleted in later versions.<br>Compilation type. The values are as follows:<br><br>  - 0: exact compilation. Exact compilation means that the system compiles directly according to the dimension information specified by the user without any escaping during compilation. AI CPU operators are not affected by this flag.<br>  - 1: fuzzy compilation. Fuzzy compilation means that for operators that support dynamic shapes, the system generalizes the variable dimensions before compilation. If the user cannot obtain the shape range of the operator but wants to compile once to achieve multiple inference executions, the fuzzy compilation feature can be used.<br><br>The default value is 0.<br>Usage constraint: Currently, only operators involved in the transformer network model are supported. | No |
| op | string | Operator type. | Yes |
| name | string | Name of the single operator model file.<br>If the name parameter is not set, the model file is named by default as follows: sequence number_operator type_input description (dataType_format_shape)_output description (dataType_format_shape), for example, 0_Add_3_2_3_3_3_2_3_3_3_2_3_3.om.<br>For the enumeration values corresponding to dataType and format, see the `${INSTALL_DIR}/include/graph/types.h` file. The enumeration values increase sequentially. Replace `${INSTALL_DIR}` with the file storage path after the CANN software is installed. For example, if the software is installed by the root user, the default storage path is `/usr/local/Ascend/cann`. | No |
| input_desc | TensorDesc array | Operator input description. | Yes |
| output_desc | TensorDesc array | Operator output description. | Yes |
| attr | Attr array | Operator attributes. | No |

**Table 2** TensorDesc array parameters

| Attribute Name | Type | Description |
| --- | --- | --- |
| dynamic_input | string | Optional. Dynamic input. The value must be the same as the input name defined for the operator in the operator information library.<br>This parameter is used to set the groups and number of dynamic inputs of the operator. For example, the dynamic inputs of an operator in the operator prototype definition are as follows:<br>.DYNAMIC_INPUT(x,...)<br>.DYNAMIC_INPUT(y,...)<br>This indicates that there are two groups of dynamic inputs: x and y. The number of inputs in each group is determined by the number of dynamic_input entries. For the specific setting principles, see the description of the name parameter in the TensorDesc array.<br><br>  - If the name parameter has been set in the constructed single operator description file, this parameter is optional.<br>  - If the name parameter is not set in the constructed single operator description file, this parameter is required.<br>  - If both dynamic_input and name parameters exist, the setting of the name parameter takes precedence. |
| format | string | Required. Format actually used during the Tensor computation process, also called the runtime format, corresponding to the format used for computation on the Device.<br>The currently supported Format values and their corresponding enumerations are as follows:<br><br>  - NCHW: 0<br>  - NHWC: 1<br>  - ND: 2, indicating that any format is supported.<br>  - NC1HWC0: 3, 5-dimensional data format.<br>  - FRACTAL_Z: 4, used to define the data format of convolution weights.<br>  - FRACTAL_NZ: 29, fractal format. For details about the preceding Format values, see [Key Concepts](../overview/atc_overview.md#key-concepts).<br>  - RESERVED: 40. When there is an optional input and the optional input has no input data, the format of the optional input must be set to RESERVED and the type must be set to UNDEFINED. If the optional input has input data, set the format and type according to the input data.<br><br>After model conversion, the preceding Format values are presented as the corresponding enumerations in the om offline model file name. For example, if the input is in NHWC format, it is displayed as 1. |
| origin_format | string | Optional. Original format of the Tensor input, that is, the original image format without any conversion.<br>If this field is not specified, the format used during the Tensor computation process is the same as the original format by default. |
| name | string | Optional. Name of the Tensor. This field must be set when the operator input is a dynamic input.<br>This parameter is used to set the name of each specific input in each group of dynamic inputs. Each input name is the input name defined in the operator prototype plus a number. The number is determined by the number of dynamic_input entries and increases sequentially from 0.<br><br>  - If the dynamic_input parameter has been set in the constructed single operator description file, this parameter is optional.<br>  - If the dynamic_input parameter is not set in the constructed single operator description file, this parameter is required.<br>  - If both dynamic_input and name parameters exist, the setting of the name parameter takes precedence. |
| shape | int array | Required. Shape actually used during the Tensor computation process, for example, [1, 224, 224, 3]. The product of the actual shape cannot exceed the maximum int32 value (2147483647).<br><br>  - Static shape scenario: The shape dimensions and values are all fixed. In this scenario, the shape_range parameter does not need to be configured.<br>  - Constant shape scenario: If the operator input and output shapes are expected to be scalars, this parameter must be set to "[]", for example, "shape": []. In this scenario, the shape_range parameter does not need to be configured.<br>  - Dynamic shape scenario: The shape values are as follows:<br>  &nbsp;&nbsp;· The shape dimensions are determined, but the value of a certain dimension is uncertain. In this case, set the value of the uncertain dimension to "-1", for example, [16,-1,20,-1]. In this scenario, the shape_range parameter must be used together to specify the value range of the "-1" dimension. For example:<br> &nbsp;&nbsp;&nbsp;&nbsp;"shape": [-1,16],<br> &nbsp;&nbsp;&nbsp;&nbsp;"shape_range": [[0,32]],<br>  &nbsp;&nbsp;· The shape dimensions are also uncertain. In this scenario, the shape value is "-2", for example, "shape": [-2]. In this scenario, the shape_range parameter does not need to be configured (not supported in the current version).<br>In the dynamic shape operator execution scenario, the installed version of the operator library package in the operator execution environment must be consistent with the version of the operator model compilation environment. Otherwise, an error is reported when the operator is loaded. For details, see [Failure to Load a Single Operator Due to an Operator Library Package Version Issue](../FAQ/operator_library_version_error.md). |
| origin_shape | string | Optional. Original shape of the Tensor input.<br>If this field is not specified, the shape used during the Tensor computation process is the same as the original shape by default. |
| type | string | Required. Data type of the Tensor. The supported types and their corresponding enumerations are as follows:<br><br>  - bool: 12<br>  - int8: 2<br>  - uint8: 4<br>  - int16: 6<br>  - uint16: 7<br>  - int32: 3<br>  - uint32: 8<br>  - int64: 9<br>  - uint64: 10<br>  - float16/fp16/half: 1<br>  - float/float32: 0<br>  - double: 11<br>  - complex32: 33<br>  - complex64: 16<br>  - complex128: 17<br>  - uint1: 30<br>  - bfloat16: 27<br>  - int4: 29<br>  - UNDEFINED: 28. When there is an optional input and the optional input has no input data, the type of the optional input must be set to UNDEFINED and the format must be set to RESERVED. If the optional input has input data, set the format and type according to the input data.<br><br>After model conversion, the preceding types are presented as the corresponding enumerations in the om offline model file name. For example, if the input is of the int8 type, it is displayed as 2. |
| shape_range | int[2] array | Optional. Value range of the unknown shape when the shape is dynamic (excluding the -2 scenario).<br>For example, if the shape value is [16,-1,20,-1], -1 indicates an unknown shape.<br>If the shape_range value is [1,128],[1,-1]: [1,128] indicates a value range from 1 to 128, corresponding to the first -1 in the shape parameter; [1,-1] indicates a value range from 1 to infinity, corresponding to the second -1 in the shape parameter. |
| is_const | bool | Optional. Indicates whether the input is a constant:<br><br>  - true: constant.<br>  - false: default value, non-constant. |
| const_value | list | Optional. Constant value.<br>Currently, only one-dimensional list configuration is supported. The number of entries in the list is determined by the shape value. For example, if the shape value is 2, the number of entries in const_value is 2.<br>The value type is determined by type. For example, if type is float16, the values in const_value are automatically converted to float16 format during single operator compilation. |

**Table 3** Attr array parameters

| Attribute Name | Type | Description |
| --- | --- | --- |
| name | string | Required. Attribute name. |
| type | string | Required. Type of the attribute value. The supported types are as follows:<br><br>  - bool<br>  - int<br>  - float<br>  - string<br>  - list_bool<br>  - list_int<br>  - list_float<br>  - list_string<br>  - list_list_int<br>  - data_type |
| value | Determined by the value of type | Required. Attribute value. The value varies depending on type. Examples are as follows:<br><br>  - bool: true/false<br>  - int: 10<br>  - float: 1.0<br>  - string: "NCHW"<br>  - list_bool: [false, true]<br>  - list_int: [1, 224, 224, 3]<br>  - list_float: [1.0, 0.0]<br>  - list_string: ["str1","str2"]<br>  - list_list_int: [[1, 3, 5, 7], [2, 4, 6, 8]]<br>  - data_type: "DT_FLOAT" or the number corresponding to the enumeration value, for example, 0. For other values, see the DataType enumeration values or the numbers corresponding to the enumeration values in `${INSTALL_DIR}/include/graph/types.h`. Replace `${INSTALL_DIR}` with the file storage path after the CANN software is installed. For example, if the software is installed by the root user, the default storage path is `/usr/local/Ascend/cann`. |
