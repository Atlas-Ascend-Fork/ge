# --op\_debug\_config

<!-- md-trans-meta sourceCommit=1dea726c9fa59e3b81454a7fd0930f2a4914fdd3 translatedAt=2026-10-22T03:27:12.481Z pushedAt=2026-10-27T11:25:07.622Z -->

## Product Support

Supported on all chips.

## Feature Description

A configuration parameter for the operator debug function, used to control Global Memory detection and operator build debugging options.

## Related Parameters

None.

## Parameter Values

**Parameter value:**
Path and file name of the configuration file.

**Parameter value format:**
Path and file name: supports uppercase and lowercase letters (a-z, A-Z), digits (0-9), underscores (\_), hyphens (-), periods (.), and Chinese characters.

**Parameter value constraints:**

The configuration file supports the following options. Separate multiple options with commas (,).

- **oom**: During operator **execution**, detects whether Global Memory is accessed out of bounds.
  - When this option is configured, during operator build, the .o (operator binary) and .json (operator description) files are reserved in the kernel\_meta folder generated by operator build in the current execution path.
  - After this option is used, the following detection logic is added during operator build. You can use the **dump\_cce** parameter to view the following code in the generated .cce file.

    ```cce
    inline __aicore__ void  CheckInvalidAccessOfDDR(xxx) {
        if (access_offset < 0 || access_offset + access_extent > ddr_size) {
            if (read_or_write == 1) {
                trap(0X5A5A0001);
            } else {
                trap(0X5A5A0002);
            }
        }
    }
    ```

- **dump\_cce**: During operator build, the operator cce file \*.cce, as well as the .o (operator binary) and .json (operator description) files, are reserved in the kernel\_meta folder generated by operator build in the current execution path.
- **dump\_loc**: During operator build, the python-cce mapping file \*\_loc.json, as well as the .o (operator binary) and .json (operator description) files, are reserved in the kernel\_meta folder generated by operator build in the current execution path.
- **ccec\_O0**: During operator build, enables the ccec compiler option -O0. This option **does not** optimize the debug information, and is used for subsequent analysis of AI Core Error issues.
- **ccec\_g**: During operator build, enables the ccec compiler option -g. This option **does** optimize the debug information, and is used for subsequent analysis of AI Core Error issues.
- **check\_flag**: During operator **execution**, checks whether the internal pipeline synchronization signals of the operator match.
  - When this option is configured, during operator build, the .o (operator binary) and .json (operator description) files are reserved in the kernel\_meta folder generated by operator build in the current execution path.
  - After this option is used, the following check logic is added during operator build. You can use the **dump\_cce** parameter to view the following code in the generated .cce file.

    ```cce
    set_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID0);
    set_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID1);
    set_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID2);
    set_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID3);
    ....
    pipe_barrier(PIPE_MTE3);
    pipe_barrier(PIPE_MTE2);
    pipe_barrier(PIPE_M);
    pipe_barrier(PIPE_V);
    pipe_barrier(PIPE_MTE1);
    pipe_barrier(PIPE_ALL);
    wait_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID0);
    wait_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID1);
    wait_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID2);
    wait_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID3);
    ...
    ```

    During actual inference, if the internal pipeline synchronization signals of the operator do not match, a timeout error is reported at the **faulty operator and the program is terminated**. An example of the error message is as follows:

    ```plaintext
    Aicore kernel execute failed, ..., fault kernel_name=operator name,...
    rtStreamSynchronizeWithTimeout execute failed....
    ```

> [!NOTE]
>
>- When the ccec compiler options (that is, the ccec\_O0 and ccec\_g options) are configured, the size of the operator kernel (the \*.o file) increases. In dynamic shape scenarios, because all possible shapes are traversed during operator build, the operator kernel file may become too large to compile. In this case, it is recommended that you do not configure the ccec compiler options.
>
>   An example of the error log when the operator kernel file is too large to compile is as follows:
>
>   ```plaintext
>   message:link error ld.lld: error: InputSection too large for range extension thunk ./kernel_meta_xxxxx.o:
>    ```
>
>- The ccec compiler option ccec\_O0 and oom cannot be enabled at the same time, which may cause an AICore Error. An example of the error message is as follows:
>
>   ```plaintext
>   ...there is an aivec error exception, core id is 49, error code = 0x4 ...
>    ```
>
>- If the NPU\_COLLECT\_PATH environment variable is configured, enabling the "check whether Global Memory is out of bounds" switch (the configuration file specified by --op\_debug\_config is set to oom) is not supported. Otherwise, the compiled model file or operator kernel package will report an error when used.
>- When the compiler options oom, dump\_cce, and dump\_loc are configured, if the model contains the following general-purpose fusion operators, the \*.o, \*.json, and \*.cce files of these operators will not be generated in the operator build directory kernel\_meta.
>
>   MatMulAllReduce
>
>   MatMulAllReduceAddRmsNorm
>
>   AllGatherMatMul
>
>   MatMulReduceScatter
>
>   AlltoAllAllGatherBatchMatMul
>
>   BatchMatMulReduceScatterAlltoAll

## Recommended Configuration and Benefits

None.

## Example

Assume that the configuration file is named gm\_debug.cfg. The following is an example of the file content:

```text
op_debug_config=ccec_g,oom
```

Upload the file to the server where the ATC tool is located, for example, to $HOME/module. The following is an example of how to use it:

```bash
atc --op_debug_config=$HOME/module/gm_debug.cfg ...
```

## Constraints

During operator build, if you do not want to build all AI Core operators but only specific AI Core operators, add the **op\_debug\_list** field to the _gm\_debug.cfg_ configuration file. During operator build, only the operators specified in this list are built, and they are built according to the options configured in op\_debug\_config. The requirements for the **op\_debug\_list** field are as follows:

- You can specify operator names or operator types.
- Separate operators with commas (,). For an operator type, configure it in the **OpType::TypeName** format. Operator types and operator names can be configured together.
- The operators to be built must be placed in the configuration file specified by the --op\_debug\_config parameter. The operator type must be the type of an operator defined based on Ascend IR. For details about how to view operator types, see [How Do I Determine the Correspondence Between Operators in the Original Framework Network Model and Operators Supported by AI Processors](../FAQ/operator_correspondence_guide.md).

The following is a configuration example:

Add the following information to the configuration file (for example, gm\_debug.cfg) specified by the --op\_debug\_config parameter:

```text
op_debug_config=ccec_g,oom
op_debug_list=GatherV2,OpType::ReduceSum
```

Upload the file to the server where the ATC tool is located, for example, to $HOME/module. The following is an example:

```bash
atc --op_debug_config=$HOME/module/gm_debug.cfg ...
```

During actual model conversion, the *GatherV2,ReduceSum* operators are built according to the ccec\_g,oom option.
