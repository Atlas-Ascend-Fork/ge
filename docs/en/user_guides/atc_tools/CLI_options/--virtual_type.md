## Feature Overview

Whether an offline model can run on the virtual device generated by the Ascend virtualization instance feature.

Current chips provide large computing power, which cloud users or small enterprises do not fully need. The Ascend virtualization instance feature supports partitioning the computing power of a chip, allowing users to apply for computing power on demand based on their own services.

The Ascend virtualization instance mainly refers to the scenario of NPU resource virtualization. Its primary purpose is to improve the utilization of physical NPU resources through mutually isolated vNPU virtual instances. A virtual device is a virtual acceleration resource applied for on a chip based on specified computing power.

## Parameter Values

- 0: (default) The offline model does not run on the virtual device generated by the Ascend virtualization instance feature.
- 1: The offline model runs on virtual devices with different computing capabilities.

## Recommended Configuration and Benefits

None.

## Example

```bash
atc --virtual_type=1 ...
```

## Constraints

- When using this parameter, ensure that the Ascend virtualization instance feature environment has been set up in the running environment.
- For the MindSpore framework:
  - The **ReduceMean** operator does not support the --virtual\_type parameter.
  <!-- npu="910,310p" id2 -->
  - The **ReverseV2** operator supports the --virtual\_type parameter only on Atlas inference products and Atlas training products.
  <!-- end id2 -->

- If [--virtual\_type](--virtual_type.md)=1 is used for model conversion, the number of logical AI Cores involved in computation of the converted offline model may be greater than the actual number of aicore\_num cores, and is the least common multiple of the configurable range supported by aicore\_num:

    For example, if the configurable range supported by aicore\_num is \{1,2,4,8\}, the number of NPU cores used to run the offline model converted with the [--virtual\_type](--virtual_type.md)=1 parameter is 8.

<!-- npu="950,A3,910b,910,310p,310b" id3 -->
- When [--virtual\_type](--virtual_type.md)=1, if the model converted using the ATC tool includes the following operators, a single core is used by default. In this scenario, the inference performance of the converted model is degraded:

  - DynamicRNN
  - PadV2D
  - SquareSumV2
  - DynamicRNNV2
  - DynamicRNNV3
  - DynamicGRUV

    <!-- npu="950" id4 -->
    This constraint is not supported on Ascend 950PR&950DT products.
    <!-- end id4 -->
