Extended operator implementations can be obtained from the Caffe, TensorFlow, and MindSpore deep learning frameworks. The first type of extended operator is implemented based on the Caffe framework, such as the ROIPooling, PSROIPooling, Normalize, and Upsample layers, and therefore has public standard prototxt definitions. The second type of extended operator is not implemented under the Caffe framework. For custom operators in such networks, standard prototxt definitions also need to be provided to define the corresponding operators in the network in the prototxt.

## Reverse

Reverses the order along the specified axes. For example, if the input is \[1,2,3\], the reversed result is \[3,2,1\].

The operator definition is as follows:

1. Add ReverseParameter to LayerParameter.

    ```c++
    message LayerParameter {
    ...
    optional ReverseParameter reverse_param = 157;
    ...
    }
    ```

2. Define the ReverseParameter type and its attribute parameters.

    ```c++
    message ReverseParameter{
      repeated int32 axis = 1;
    }
    ```

## ROIPooling

In object detection algorithms, the ROIs generated by region proposals vary in size, while the FC layers of the classification network require fixed-size input. Therefore, ROIPooling serves as a bridge between them.

The ROIPooling layer is used in the Faster RCNN network to unify the dimensions of feature maps obtained from different images after passing through convolutional layers. Its input is a feature map and the coordinates of the ROI boxes to be extracted from it, and its output is a dimension-normalized feature map.

The ROIPooling layer requires extending the caffe.proto file to define ROIPoolingParameter. The extension method is as follows, and the defined parameters include:

- spatial\_scale, that is, the size ratio between the input feature map and the original image, used to convert the ROI coordinates because the ROI coordinates are based on the original image size.
- pooled\_h and pooled\_w, the height (h) and width (w) of the output feature map in the spatial dimension.

1. Add ROIPoolingParameter to LayerParameter

    ```c++
    message LayerParameter {
    ...
    optional ROIPoolingParameter roi_pooling_param = 161;
    ...
    }
    ```

2. Define the ROIPoolingParameter type and its attribute parameters

    ```c++
    message ROIPoolingParameter {
        required int32 pooled_h = 1;
        required int32 pooled_w = 2;
        optional float spatial_scale = 3 [default=0.0625];
        optional float spatial_scale_h = 4;
        optional float spatial_scale_w = 5;
    }
    ```

Based on the preceding principles, the code sample for defining the ROIPooling layer in prototxt is as follows:

```textproto
layer {
name: "roi_pooling"
type: "ROIPooling"
bottom: "res4f"
bottom: "rois"
bottom: "actual_rois_num"
top: "roi_pool"
roi_pooling_param {
  pooled_h: 14
  pooled_w: 14
  spatial_scale:0.0625
  spatial_scale_h:0.0625
  spatial_scale_w:0.0625
  }
}
```

## PSROIPooling

The operation of the PSROIPooling layer is similar to that of the ROIPooling layer. The difference is that the image features output in different spatial dimensions come from different feature map channels, and Average Pooling is performed on each small region, unlike the Max Pooling used in ROIPooling.

For a result with an output of k\*k, the features of different spatial dimensions are taken from different groups in the input feature map. That is, the input feature map is evenly divided into k\*k groups, and the number of channels in each group is consistent with the number of output channels, producing the output described above.

The PSROIPooling layer requires extending the caffe.proto file to define PSROIPoolingParameter. The extension method is as follows, and the defined parameters include:

- spatial\_scale, that is, the size ratio between the input feature map and the original image.
- output\_dim, the channel of the output feature map.
- group\_size, the output spatial dimension, that is, the k mentioned above.

1. Add PSROIPoolingParameter to LayerParameter.

    ```c++
    message LayerParameter {
    ...
    optional PSROIPoolingParameter psroi_pooling_param = 207;
    ...
    }
    ```

2. Define the PSROIPoolingParameter type and its attribute parameters.

    ```c++
    message PSROIPoolingParameter {
       required float spatial_scale = 1;
       required int32 output_dim = 2; // output channel number
       required int32 group_size = 3; // number of groups to encode position-sensitive score maps
    }
    ```

Based on the preceding principles, the code sample for defining the PSROIPooling layer in prototxt is as follows:

```textproto
layer {
  name: "psroipooling"
  type: "PSROIPooling"
  bottom: "some_input"
  bottom: "some_input"
  top: "some_output"
  psroi_pooling_param {
    spatial_scale: 0.0625
    output_dim: 21
    group_size: 7
  }
}
```

## Upsample

The Upsample layer is the inverse operation of the Pooling layer. Each Upsample layer corresponds one-to-one with a preceding Pooling layer of matching input and output sizes in the network, expanding the feature map in the spatial dimension.

The Upsample layer requires extending the caffe.proto file to define UpsampleParameter. An example of the extension method is shown below. The defined parameter includes stride, which is the size ratio of the output to the input, such as 2.

1. Add UpsampleParameter to LayerParameter

    ```c++
    message LayerParameter {
    ...
    optional UpsampleParameter upsample_param = 160;
    ...
    }
    ```

2. Define the UpsampleParameter type and its attribute parameters

    ```c++
        optional float scale = 1[default = 1];
        optional int32 stride = 2[default = 2];
        optional int32 stride_h = 3[default = 2];
    ```

## Normalize

The Normalize layer is a normalization layer in SSD networks. Its main purpose is to normalize elements in the spatial or channel dimension to the range of 0 to 1. For a three-dimensional tensor of c\*h\*w, the output is a tensor of the same size. The intermediate computation normalizes each element by the square root of the sum of squares along the channel direction. The specific formula is as follows:

$$
x_i' = \frac{x_i}{\sqrt{\sum_{i=1}^{c} x_i^2}}
$$

The accumulated vector of the sum of squares in the denominator consists of all vectors along the c direction at the same h and w positions, as shown in the orange area in [Figure 1](#fig1).

**Figure 1**  Normalize layer principle diagram<a id="fig1"></a>
![](../figures/normalize_layer_principle.png "Normalize layer principle diagram")

After the normalization described above, a scale is applied to each feature map, with one scale value corresponding to each channel.

The Normalize layer requires extending the caffe.proto file to define NormalizeParameter. The extension method is as follows. The defined parameters include:

- The across\_spatial parameter indicates whether to normalize the entire image, with the normalization dimension being 1 x c x h x w. Otherwise, normalization is performed for each pixel: 1 x c x 1 x 1.
- channel\_shared indicates whether the scale values are the same. If true, all scale values are the same. Otherwise, the scale values are the same for the channel but differ for pixels in different channels. The default value is True.
- eps is a very small value that prevents division by zero during normalization. The default value is 1e-10 and it is configurable.

The calculation formula of normalize is converted to:

$$
x_i = \frac{x_i}{\sqrt{\sum_{i=1}^{n} x_i^2 + \text{eps}}} \times \text{scale}_i
$$

The operator definition is as follows:

1. Add NormalizeParameter to LayerParameter

    ```c++
    message LayerParameter {
    ...
    optional NormalizeParameter norm_param = 206;
    ...
    }
    ```

2. Define the NormalizeParameter type and attribute parameters

    ```c++
    message NormalizeParameter {
      optional bool across_spatial = 1 [default = true];
      // Initial value of scale. Default is 1.0 for all
      optional FillerParameter scale_filler = 2;
      // Whether or not scale parameters are shared across channels.
      optional bool channel_shared = 3 [default = true];
      // Epsilon for not dividing by zero while normalizing variance
      optional float eps = 4 [default = 1e-10];
    }
    ```

Based on the preceding principles, the code sample for defining Normalize in prototxt is as follows:

```textproto
layer {
  name: "normalize_layer"
  type: "Normalize"
  bottom: "some_input"
  top: "some_output"
  norm_param {
    across_spatial: false
    scale_filler {
      type: "constant"
      value: 20
    }
    channel_shared: false
  }
}
```

## Reorg

The Reorg operator is presented as the PassThrough operator inside the AI processor, transferring channel data to the plane, or performing the reverse operation.

The PassThrough layer is a custom layer in Yolo v2. Since Yolo v2 is not implemented using the Caffe framework, there is no standard definition for this layer. The function implemented by this layer is to expand the data of the feature map from the spatial dimension to the channel dimension. Elements that are originally consecutive in the channel dimension remain consecutive in the expanded feature map.

## ROIAlign

ROIAlign is a region feature aggregation method proposed in the Mask R-CNN paper. It improves on the ROIPooling algorithm by replacing the two quantization operations in ROIPooling with bilinear interpolation, thereby solving the region mismatch problem caused by ROIPooling and improving detection accuracy.

The ROIAlign operator obtains an ROI (range of interest) from the feature map, divides it into pooled\_w x pooled\_h cells, and further divides each cell into sampling\_ratio\*sampling\_ratio small squares. The center of each small square is a sampling point. As shown in [Figure 3](#fig3), the dashed lines represent the feature map and the solid lines represent the ROI, where the ROI is divided into 2x2 cells. If the number of sampling points is 4, each cell is first divided into four small squares (as shown by the red lines), and the center of each small square is a sampling point. Since the coordinates of sampling points are usually floating-point numbers, bilinear interpolation is required for the sampling point pixels (as shown by the four arrows in [Figure 3](#fig3)) to obtain the value of that pixel. Then the four sampling points in each cell are averaged to obtain the final ROIAlign result.

**Figure 3**  ROIAlign principle<a id="fig3"></a>
![](../figures/roialign_principle.png "ROIAlign principle")

The operator definition is as follows:

1. Add ROIAlignParameter to LayerParameter

    ```c++
    message LayerParameter {
    ...
     optional ROIAlignParameter  roi_align_param = 154;
    ...
    }
    ```

2. Define the ROIAlignParameter type and attribute parameters

    ```c++
    message ROIAlignParameter {
      // Pad, kernel size, and stride are all given as a single value for equal
      // dimensions in height and width or as Y, X pairs.
      optional uint32 pooled_h = 1 [default = 0]; // The pooled output height
      optional uint32 pooled_w = 2 [default = 0]; // The pooled output width
      // Multiplicative spatial scale factor to translate ROI coords from their
      // input scale to the scale used when pooling
      optional float spatial_scale = 3 [default = 1];
      optional int32 sampling_ratio = 4 [default = -1];
      optional int32 roi_end_mode = 5 [default = 0];
    }

    ```

Based on the preceding types and attributes, you can customize the prototxt.

## Yolo

The YOLO operator appears in the YOLO V2 network and is currently used only in the YOLO V2 and V3 networks, performing sigmoid and softmax operations on the data.

- In YOLO V2, there are four scenarios depending on the background and softmax parameters:
    1. background=false, softmax=true,

        Apply sigmoid to \(x,y\) in \(x,y,h,w\), apply sigmoid to b, and apply softmax to classes.

    2. background=false, softmax=false,

        Apply sigmoid to \(x,y\) in \(x,y,h,w\), apply sigmoid to b, and apply sigmoid to classes.

    3. background=true, softmax=false,

        Apply sigmoid to \(x,y\) in \(x,y,h,w\), do not compute b, and apply sigmoid to classes.

    4. background=true, softmax= true,

        Apply sigmoid to \(x,y\) in \(x,y,h,w\), and apply softmax to b and classes together.

- In YOLO V3, there is only one scenario: apply sigmoid to \(x,y\) in \(x,y,h,w\), apply sigmoid to b, and apply sigmoid to classes.

The input data format is Tensor\(n, coords+background+classes,l.h,l.w\), where n is the number of anchor boxes, and coords represents x, y, w, h.

The operator definition is as follows:

1. Add YoloParameter to LayerParameter.

    ```c++
    message LayerParameter {
    ...
     optional YoloParameter yolo_param = 199;
    ...
    }
    ```

2. Define the YoloParameter type and attribute parameters.

    ```c++
    message YoloParameter {
      optional int32 boxes = 1 [default = 3];
      optional int32 coords = 2 [default = 4];
      optional int32 classes = 3 [default = 80];
      optional string yolo_version = 4 [default = "V3"];
      optional bool softmax = 5 [default = false];
      optional bool background = 6 [default = false];
      optional bool softmaxtree = 7 [default = false];
    }
    ```

Based on the preceding principles, the code sample for defining Yolo in prototxt is as follows:

## PriorBox

Generates prior boxes based on the input parameters.

The following uses conv7\_2\_mbox\_priorbox as an example to describe how the number of prior boxes is generated based on the corresponding parameters. The definition is as follows:

```textproto
layer{
    name:"conv7_2_mbox_priorbox"
    type:"PriorBox"
    bottom:"conv7_2"
    bottom:"data"
    top:"conv7_2_mbox_priorbox"
    prior_box_param{
        min_size:162.0
        max_size:213.0
        aspect_ratio:2
        aspect_ratio:3
        flip:true
        clip:false
        variance:0.1
        variance:0.1
        variance:0.2
        variance:0.2
        img_size:300
        step:64
        offset:0.5
    }
}
```

1. Generate a prior box with both width and height equal to min\_size.
2. If max\_size exists, use sqrt\(min\_size\*max\_size\) to determine the width and height and generate a box (constraint: max\_size\>min\_size).
3. Generate the corresponding prior boxes based on aspect\_ratio (as shown in the definition, aspect\_ratio is 2, 3, and flip is true, so aspect\_ratio=1/2 and 1/3 are automatically added).

Therefore, num\_priors (the number of prior boxes) = the number of min\_size + the number of aspect\_ratio (4 here) × the number of min\_size (1 here) + the number of max\_size (where the number of max\_size corresponds one-to-one with the number of min\_size).

The operator definition is as follows:

1. Add PriorBoxParameter to LayerParameter.

    ```c++
    message LayerParameter {
    ...
     optional PriorBoxParameter prior_box_param = 203;
    ...
    }
    ```

2. Define the PriorBoxParameter type and attribute parameters.

    ```c++
    message PriorBoxParameter {
      // Encode/decode type.
      enum CodeType {
        CORNER = 1;
        CENTER_SIZE = 2;
        CORNER_SIZE = 3;
      }
      // Minimum box size (in pixels). Required!
      repeated float min_size = 1;
      // Maximum box size (in pixels). Required!
      repeated float max_size = 2;
      // Various of aspect ratios. Duplicate ratios will be ignored.
      // If none is provided, we use default ratio 1.
      repeated float aspect_ratio = 3;
      // If true, will flip each aspect ratio.
      // For example, if there is aspect ratio "r",
      // we will generate aspect ratio "1.0/r" as well.
      optional bool flip = 4 [default = true];
      // If true, will clip the prior so that it is within [0, 1]
      optional bool clip = 5 [default = false];
      // Variance for adjusting the prior bboxes.
      repeated float variance = 6;
      // By default, we calculate img_height, img_width, step_x, step_y based on
      // bottom[0] (feat) and bottom[1] (img). Unless these values are explicitly
      // provided.
      // Explicitly provide the img_size.
      optional uint32 img_size = 7;
      // Either img_size or img_h/img_w should be specified; not both.
      optional uint32 img_h = 8;
      optional uint32 img_w = 9;

      // Explicitly provide the step size.
      optional float step = 10;
      // Either step or step_h/step_w should be specified; not both.
      optional float step_h = 11;
      optional float step_w = 12;

      // Offset to the top left corner of each cell.
      optional float offset = 13 [default = 0.5];
    }
    ```

## SpatialTransformer

The computation of this operator actually performs an affine transformation: the parameters of the affine transformation can be fixed in the prototxt, with one copy shared across multiple batches, or they can be the second input of the layer, with different parameters used for each batch.

Calculation steps:

1. For the output coordinates, transform them into values in the \[-1,1\] interval using the following formulas.

    $$
    X' = x \times \frac{1.0}{\text{out}_h} \times 2 -1
   $$

    $$
    y' = y \times \frac{1.0}{\text{out}_w} \times 2 -1
   $$

    The calculation code is as follows:

    ```c++
    Dtype* data = output_grid.mutable_cpu_data();
             for(int i=0; i< output_H_ * output_W_; ++i) {
                       data[3 * i] = (i / output_W_) * 1.0 / output_H_ * 2 - 1;
                       data[3 * i + 1] = (i % output_W_) * 1.0 / output_W_ * 2 - 1;
                       data[3 * i + 2] = 1;
             }
    ```

2. Convert to the input coordinates through the affine transformation, where s denotes the input coordinates and t denotes the output coordinates. The calculation formula is as follows:

    $$
    \begin{pmatrix}
    x_i^s \\
    y_i^s
    \end{pmatrix}
    =
    \begin{bmatrix}
    \theta_{11} & \theta_{12} & \theta_{13} \\
    \theta_{21} & \theta_{22} & \theta_{23} \\
    \end{bmatrix}
    \begin{pmatrix}
    x_i^t \\
    y_i^t
    1
    \end{pmatrix}
    $$

    The calculation code is as follows:

    ```c++
    caffe_cpu_gemm<Dtype>(CblasNoTrans, CblasTrans, output_H_ * output_W_, 2, 3, (Dtype)1.,
          output_grid_data, full_theta_data + 6 * i, (Dtype)0., coordinates);
    ```

3. Obtain the value at the corresponding position from the input coordinates and assign it to the corresponding position of the output.

    Because the output coordinates are transformed once in the first step, the corresponding input coordinates are scaled back in the same way. The code sample is as follows:

    ```c++
    Dtype x = (px + 1) / 2 * H;
    Dtype y = (py + 1) / 2 * W;
             if(debug) std::cout<<prefix<<"(x, y) = ("<<x<<", "<<y<<")"<<std::endl;

      for(int m = floor(x); m <= ceil(x); ++m)
        for(int n = floor(y); n <= ceil(y); ++n) {
                 if(debug) std::cout<<prefix<<"(m, n) = ("<<m<<", "<<n<<")"<<std::endl;
                 if(m >= 0 && m < H && n >= 0 && n < W) {
                            res += (1 - abs(x - m)) * (1 - abs(y - n) * pic[m * W + n]);
                           if(debug) std::cout<<prefix<<" pic[m * W + n]= "<<std::endl;
                 }
        }
    ```

The operator definition is as follows:

1. Add SpatialTransformParameter to LayerParameter.

    ```c++
    message LayerParameter {
    ...
     optional SpatialTransformParameter spatial_transform_param = 153;
    ...
    }
    ```

2. Define the SpatialTransformParameter type and its attribute parameters.

    ```c++
    message SpatialTransformParameter {
      optional uint32 output_h = 1 [default = 0];
      optional uint32 output_w = 2 [default = 0];
      optional float border_value = 3 [default = 0];
      repeated float affine_transform = 4;
      enum Engine {
        DEFAULT = 0;
        CAFFE = 1;
        CUDNN = 2;
      }
      optional Engine engine = 15 [default = DEFAULT];
    }
    ```

Based on the preceding principles, the code sample for defining the SpatialTransform layer in prototxt is as follows:
