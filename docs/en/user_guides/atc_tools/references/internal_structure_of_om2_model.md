# om2 Model Internal Structure

<!-- md-trans-meta sourceCommit=43fb2994120faf2fa52f38a4d5bdf86be1691929 translatedAt=2026-11-16T15:14:48.803Z pushedAt=2026-11-17T12:53:56.787Z nl=2 -->

Run the unzip  \*.om2 command on the Linux server to decompress the model file. After entering the decompressed directory, the internal structure is as follows:

```tree
<model_name>
├── manifest.json                                   # Package manifest: version compatibility information, number of models, ATC command, etc.
└── data
    ├── model_{model_no}                            # {model_no}: indicates the model sequence number packed into om2. If there is only one model, the sequence number is 0.
    │   ├── debug                                  # Debug information
    │   │   └── ge_visual_00000000_graph_0.json     # The graph information supports visualization and can be opened and viewed using tools such as Netron.
    │   ├── model_meta.json                        # Basic information of the model
    │   ├── op_attr.json                           # Attribute information of operators
    │   ├── constants_config.json                  # Constants and weight configuration of the model
    │   ├── variables_config.json                  # Variable configuration
    │   └── runtime                                # When the model executes
    │       ├── csrc                               # Model source code and project files
    │       │   ├── <model_name>_args_manager.cpp   # args management module of operators in the model
    │       │   ├── <model_name>_internal.h         # Header file, for internal use inside the om2 model
    │       │   ├── <model_name>_kernel_reg.cpp     # Implementation of operator binary kernel registration in the model
    │       │   ├── <model_name>_load_and_run.cpp   # API implementation of operator loading and execution in the model
    │       │   ├── <model_name>_resources.cpp      # Implementation of model resource initialization
    │       │   ├── Makefile                       # Compilation project file
    │       │   └── om2_model_api.h                # Header file, containing API declarations for model loading, execution, and destruction, involving interaction with the OM2 executor
    │       └── lib<model_name>_om2.so              # .so generated by compiling the code when the model executes
    ├── kernels                                    # Operator binaries
    │   └── te_add_xxxx.o
    ├── custom_ops                                 # Custom operators
    │   ├── binaries_npu_arch                      # Custom operator binaries, file name format: kernelName_hashId_CustomKernel.bin
    │   │   └── <kernel_name>_<file_hash>_CustomKernel.bin
    │   └── shared_libs                            # Custom operator host .so
    │       └── <file_size>_<file_hash>_<original_so_name>.so
    ├── constants                                  # Constants and weight data of all models
    │   └── constant_{model_no}                     # Built-in weights
    └── variables                                  # Variable initialization data
        └── var_weight_data_{model_no}              # Variable initialization data of the corresponding model
```

For detailed descriptions of the JSON files in the internal structure and the fields they include, see [manifest.json](#manifestjson), [model\_meta.json](#model_metajson), and [constants\_config.json](#constants_configjson) respectively. The data in the files is provided as an example; refer to the information in the actual model.

## manifest.json

```json
{
    "atc_command": "/usr/local/Ascend/cann-xxx/{arch}-linux/bin/atc.bin --model=./resnet50.onnx --framework=5 --output=./resnet50 --soc_version={soc_version} --mode=7 --external_weight=1",
    "compatibility": {
        "compiler_version": "1.0",
        "required_executor_version": "",
        "used_features": {}
    },
    "model_num": 1
}
```

- atc\_command: ATC command used to generate om2.
- model\_num: Number of models included.
- compatibility: Version compatibility information.
    - compiler\_version: Compiler version used to generate the model.
    - required\_executor\_version: Minimum executor version required by the model. The value is the maximum among the executor versions required by the features used by the model; it is an empty string when no feature is used.
    - used\_features: Mapping from the feature names used by the model to the executor version strings required by the features; it is an empty object when no feature is used.

The version numbers above are provided as an example; refer to the information in the actual model.

## model\_meta.json

```json
{
    "dynamic_dims": {
        "dynamic_type": 1,
        "user_designate_shape_order": ["actual_input_1"],
        "gears": [
            {
                "inputs": [1],
                "outputs": [[1, 1000]]
            },
            {
                "inputs": [16],
                "outputs": [[16, 1000]]
            }
        ]
    },
    "inputs": [
        {
            "data_type": 0,
            "format": 0,
            "index": 0,
            "name": "actual_input_1",
            "shape": [
                -1,
                3,
                224,
                224
            ],
            "max_gear_shape": [
                16,
                3,
                224,
                224
            ],
            "shape_range": [],
            "size": 9633792
        }
    ],
    "name": "resnet50",
    "outputs": [
        {
            "data_type": 0,
            "format": 2,
            "index": 0,
            "name": "PartitionedCall_Gemm_174_add_4:0:output1",
            "shape": [
                16,
                1000
            ],
            "shape_range": [],
            "size": 64000
        }
    ],
    "work_size": 86770688,
    "zero_copy_size": 2255360
}
```

- inputs: Model input information, which is an array. The detailed fields are as follows:
    - data\_type: Data type of the input.
    - format: Format of the input.
    - index: Index number of the input.
    - name: Input name.
    - shape: Dimension information of the input tensor. In the dynamic gear scenario, the value is the dimension information of the original input.
    - shape\_range: Dimension range of the input tensor.
    - max\_gear\_shape: Input dimension corresponding to the maximum gear, generated only in the dynamic gear scenario.
    - shape\_aclmdlGetInputDimsV2: Input dimension used for `aclmdlGetInputDimsV2` query, generated only when the model's AIPP configuration list is not empty.
    - size: Size of the input tensor.

- name: Model name.
- outputs: Model output information, which is an array. The detailed fields are as follows:
    - data\_type: Data type of the output.
    - format: Format of the output.
    - index: Index number of the output.
    - name: Output name.
    - shape: Dimension information of the output tensor.
    - shape\_range: Dimension range of the output tensor.
    - size: Size of the output tensor.

- work\_size: Working memory size used by the model. Unit: byte.
- zero\_copy\_size: Zero-copy size. Unit: byte.
- dynamic\_dims: Dynamic gear configuration, generated only when the model's dynamic gear information is not empty. The detailed fields are as follows:
    - dynamic\_type: Dynamic dimension information supported by the input, used to generate the model description information.
    - user\_designate\_shape\_order: Order of the input shape information specified by the user, which is a string array.
    - gears: Gear array, where each item contains inputs and outputs.
        - inputs: Value of each dynamic dimension in the current gear, which is an integer array.
        - outputs: Dimension of each output in the current gear, which is a two-dimensional integer array.
- aipp: AIPP configuration, generated only when the model's AIPP configuration list is not empty. aipp\_infos is a configuration array that retains only entries that are not empty and whose type is not `DATA_WITHOUT_AIPP`.

## constants\_config.json

```json
{
    "consts": {
        "dynamic_const_523670_107_78daf6e19d54b25d13695263c5bf9533ef419ab3cecc6c863d31e58125ee2e": {
            "file_name": "weight_78daf6e19d54b25d13695263c5bf9533ef419ab3cecc6c863d31e58125ee2e",
            "index": 107,
            "offset": 0,
            "size": 4096000,
            "type": "INDIVIDUAL"
        },
        "dynamic_const_523670_108_f2c712e3e81fb5fd0a67fa0edeba4e7e1943a4c04e7fff1679708ece3820ef": {
            "file_name": "weight_f2c712e3e81fb5fd0a67fa0edeba4e7e1943a4c04e7fff1679708ece3820ef",
            "index": 106,
            "offset": 0,
            "size": 2000,
            "type": "INDIVIDUAL"
        },
        "constant_105": {
            "file_name": "constant_0",
            "index": 105,
            "offset": 0,
            "size": 128,
            "type": "INTERNAL"
        }
    },
    "internal_weight_size": 128
}
```

- consts: Configuration object of the const nodes in the model.
    - key: Internal weights use constant\_\{index\}, and external weights use the corresponding computation graph node name.
        - file\_name: Weight file name corresponding to the const node. For internal weights, it is constant\_\{model\_no\}.
        - index: Index corresponding to the const node, for internal use.
        - offset: Offset of the weight file corresponding to the const node. Unit: byte. For internal use.
        - size: Weight size.
        - type: Indicates the weight type, including the following values:
            - INTERNAL: Internal weight.
            - INDIVIDUAL: Weight externalization without normalization.
            - COMBINED: Weight externalization with normalization.

- internal\_weight\_size: Total size of built-in weights. If all weights are externalized, the value is 0.
